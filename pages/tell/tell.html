INTRODUCTION TO GUIDED TOURS

Beyond freely wandering through its data landscapes, the Second Realm offers the option to follow a guided tour.

A guided tour is an ordered collection of short stories tied to specific points of interest within a realm. This collection forms a circuit, serving as an Ariadne’s thread to guide explorers through their immersive journey.

DESCRIPTOR FILES FORMAT

A guided tour is defined by a descriptor file in JSON format, associated with the realm by its builder during configuration. An example of a descriptor file can be found here.

The structure of all descriptor files follows this format:

version: The version of the Descriptor File format. Value should be 0.2.0

type: The type of descriptor file. Value should be "guided_tour" (manual piloting) or "guided_tour_autopilot" (autopilot mode)

title: The name of the Guided Tour. Value should be a string.

lang (optional): Language of the Guided Tour. Value should be a 2-letter language code (ISO 639-1). Currently supported values are: en | fr

voice_level: Volume level of the audioguide. Value should be a decimal value between 0.0 and 3.0.

music_level: Volume level of the background music. Value should be a decimal value between 0.0 and 3.0.

coords_type: The coordinate system used in the file. The value should be either "data_series" or "block_height".

  • data_series: Coordinates are expressed as an array of three numerical values [X, Y, Z] representing a point in the data space, dependent on the metrics selected for each axis.
  • block_height: Coordinates are expressed as a single integer value representing the height of a block.

initial_pos: The initial position of the explorer. The format depends on the "coords_type" value.

stages: An array of points of interest (stages). Each stage is an object with the following structure:

  • coords: The coordinates of the point of interest. The format depends on the "coords_type" value.
  • title: The name or title of the stage.
  • desc: The content associated with the stage.
  • filters (optional): Filters applied when the stage is reached, hiding points of the cloud that fall outside the given bounds. Value should be an array of groups. A point stays visible if it matches at least one group.
    • Each group is an array of constraints of the form ["x"|"y"|"z", min, max]. A point matches a group if its data values lie within all of these inclusive ranges.
    • Bounds are expressed in data values. If an axis uses a logarithmic scale, the bounds are converted automatically.

INTRODUCTION TO AUTOMATED WANDERINGS

Not every ballad requires words. Sometimes the beauty of the landscape tells its own story.

An automated wandering consists of an ordered set of waypoints. Together, they create a circuit that the dataship follows automatically.

Each waypoint can optionally carry a short story—a title, a text, and an audio clip—displayed when the dataship reaches it.

DESCRIPTOR FILES FORMAT

An automated wandering is defined by a descriptor file in JSON format, associated with the realm by its builder during configuration. An example of a descriptor file with waypoints only can be found here. An example with text, audio and filters at each stage can be found here.

The structure of all descriptor files follows this format:

version: The version of the Descriptor File format. Value should be 0.2.0

type: The type of descriptor file. Value should always be "autopilot"

title: The name of the Automated Wandering. Value should be a string.

lang (optional): Language of the Automated Wandering. Value should be a 2-letter language code (ISO 639-1). Currently supported values are: en | fr

voice_level: Volume level of the audioguide. Value should be a decimal value between 0.0 and 3.0.

music_level: Volume level of the background music. Value should be a decimal value between 0.0 and 3.0.

coords_type: The coordinate system used in the file. The value should be either "data_series" or "block_height".

  • data_series: Coordinates are expressed as an array of three numerical values [X, Y, Z] representing a point in the data space, dependent on the metrics selected for each axis.
  • block_height: Coordinates are expressed as a single integer value representing the height of a block.

stages: An array of waypoints (stages). Each stage is an object with the following structure:

  • coords: The coordinates of the waypoint. The format depends on the "coords_type" value.
  • title (optional): The name or title of the stage.
  • desc (optional): The content associated with the stage. If at least one stage defines a description, the HUD displays that content when the stage is reached, instead of the remaining-time progress message.
  • audiofile (optional): URL of an audio clip played when the stage is reached.
  • filters (optional): Filters applied when the stage is reached, hiding points of the cloud that fall outside the given bounds. Value should be an array of groups. A point stays visible if it matches at least one group.
    • Each group is an array of constraints of the form ["x"|"y"|"z", min, max]. A point matches a group if its data values lie within all of these inclusive ranges.
    • Bounds are expressed in data values. If an axis uses a logarithmic scale, the bounds are converted automatically.

THE TOUR BUILDER

The Tour Builder is a tool displayed on the left of the HUD when immersion is entered in builder mode. This tool allows to create and edit the stages composing the skeleton of the tour. The panel lists the stages of the tour associated with the scene or an empty circuit when none has been set. From here the builder lays the stages, tries the journey, and carries the result back as a descriptor file.

The button bar above the list offers the following actions:

  • TOUR TYPE: Cycles the type of the tour among the three journeys described above: a guided tour, a guided tour on autopilot, or an automated wandering. The label shows the type currently selected.
  • SPAWN POSITION: Records the current position and orientation as the scene's spawn.
  • ADD STAGE: Adds a new stage to the tour. The current position is used for the coordinates of the stages and a virtual keyboard is used to enter the title of the stage.
  • MODE: Switches between EDIT AND TEST modes. TEST mode allows to test the tour without having to export the descriptor file. EDIT mode allows to edit the tour.
  • EXPORT: Downloads the descriptor as a JSON file stored on the disk of the headset. If a tour file is already associated with the realm, the export keeps all its existing fields and applies the edits made in the panel.

Each stage in the list carries its own buttons:

  • UP: Moves the stage one place earlier in the circuit.
  • DOWN: Moves the stage one place later in the circuit.
  • GO: Teleports the dataship to the location of the stage.
  • FLT: Opens the filter editor for the stage.
  • DEL: Removes the stage from the list.

The filter editor allows to edit the filters applied to the points cloud when the dataship reaches the stage. A point stays visible when it matches at least one group (the groups composing a filter are connected by an OR logical condition), and a group matches when the point lies inside every range of that group (the ranges of a group are connected by AND logical conditions). The points cloud updates with each change, so the result can be judged in place.

The bar at the bottom of the filter editor offers the following buttons:

  • ADD GROUP: Adds a group. A new group starts with one range covering the whole X axis, so every point still matches it until the bounds are narrowed.
  • GO: Teleports the dataship to the stage, which gives a view of the filter from the stage itself.
  • BACK: Closes the editor, returns to the stage list, and shows every point of the cloud again.

Each group is a row labeled GROUP that carries the following buttons:

  • + RANGE: Adds a range to the group. A new range covers a whole axis, so it leaves the cloud unchanged until its bounds are narrowed.
  • DEL: Removes the group. Removing the last group clears the filter of the stage.

Each range is a row of its own:

  • X, Y, Z or HEIGHT: The axis of the range. The button cycles through the three data axes and HEIGHT, the block height, stored as "key" in the descriptor. Changing the axis resets the bounds to the full extent of the new axis.
  • MIN and MAX: The inclusive bounds, expressed in data values. Selecting a bound opens the virtual keyboard on its numeric keys. HERE fills the field with the value of the current position on the selected axis, and Enter confirms the number.
  • DEL: Removes the range. Removing the last range of a group removes the group.

TIPS

Using data values as coordinates allows points of interest to be defined independently of block positions, making it easier to fine-tune their placement for optimal visibility. However, this approach requires that the guided tour be used with realms configured with the same metrics for all three axes.

The guided tour is not just about the story—it’s also about the journey. The order of the points of interest significantly impacts the experience.
